Idea brief

Problem. Indian classrooms, labs and offices waste a large share of their electricity on lights, fans and ACs running in empty parts of a room. Fifteen students in one corner of a 60-seat room still power every light row and fan. Wall switches treat the whole room as one unit, and PIR timers switch lights off on students who are sitting still. For colleges and schools on commercial tariffs, this is a recurring, avoidable cost.

Solution. SmartZone divides a room into zones. 24 GHz mmWave sensors (HLK-LD2410C) detect people even when they sit still, and an ESP32 keeps only the appliances near them running. Empty zones switch off after a configurable delay. It understands shared wiring: a light row serving two zones turns off only when both are empty. ACs are controlled through their own IR protocol with a 3-minute compressor lockout, never by a relay. Switching logic runs on the ESP32 itself, so the room keeps working if Wi-Fi or the cloud goes down. No cameras.

Cloud layer. Each ESP32 reports to a FastAPI backend on AWS. The live dashboard shows zone occupancy, manual overrides and the off-delay, and compares actual energy use against a room-switch baseline, leaving out periods with no data instead of estimating them.

Impact. About ₹3,000 of hardware per room, retrofits existing wiring, and gives savings measured in kWh. Suits schools, colleges, offices and auditoriums.

Build summary: AWS services used

  • Amazon EC2 (Ubuntu) hosts the FastAPI backend, run by uvicorn as a hardened systemd service, plus the web portal and dashboard, behind Caddy for automatic HTTPS at smartzone.anshu.tech.
  • Amazon EBS: the instance's volume stores the SQLite database of device reports and room configuration, so data survives restarts.
  • EC2 security groups: only ports 80 and 443 (web) and SSH for deployment are open; the API listens on localhost behind Caddy.
  • Deployment pipeline: GitHub Actions runs backend tests, firmware zone-logic tests, an ESP32 compile and a JS/firmware parity check, then deploys to EC2 over SSH and verifies /api/health.

Why EC2. The ESP32 needs a stable HTTPS endpoint and the backend needs a persistent database. EC2 with EBS provides both on the Free Tier without changing the existing code.

API

  • POST /api/device/report ESP32 state report, on change and every 30 s
  • GET /api/rooms/{room}/status live zones, circuits and settings
  • GET /api/rooms/{room}/energy usage vs. room-switch baseline
  • GET /api/health liveness check
